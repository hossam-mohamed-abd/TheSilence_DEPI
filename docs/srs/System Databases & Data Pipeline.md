#  System Databases & Data Pipeline Architecture

> النظام مبني على architecture متعددة الطبقات — فصل تام بين الأنظمة التشغيلية، التحليلية، وأنظمة الذكاء الاصطناعي، مع الحفاظ على ترابط كامل بين جميع الأجزاء.

**أهداف التقسيم:**
تحسين الأداء · تقليل الضغط · سهولة التوسع · دعم الـ AI · تقليل الـ Pipelines غير الضرورية

---

## قواعد البيانات

### 1.  Main Operational Database (OLTP)
> القاعدة الأساسية للتشغيل اليومي

**الغرض:** التعاملات اللحظية للمستخدمين والصيدليات.

| الجدول | الوصف |
|---|---|
| `Users` | بيانات الحسابات والصلاحيات |
| `Pharmacies` | بيانات الصيدليات والفروع |
| `Drugs` | الأدوية والمواد الفعالة والاستخدامات |
| `Inventory` | الكميات والأسعار والتوافر |
| `Orders` | الطلبات والشراء والتوصيل |
| `Search History` | عمليات البحث للمستخدمين |
| `Favorites` | الأدوية المحفوظة والمفضلة |

---

### 2.  Analytics & Data Warehouse (OLAP)
> قاعدة التحليلات والتقارير والذكاء الاصطناعي

**الغرض:** تشغيل Queries ثقيلة بعيداً عن القاعدة التشغيلية.

| البيانات المخزنة | الوصف |
|---|---|
| `Search Analytics` | أكثر الأدوية بحثاً وأنماط الاستخدام |
| `Price Trends` | تغير الأسعار بين الصيدليات مع الوقت |
| `Drug Popularity` | أكثر الأدوية انتشاراً |
| `Recommendation Logs` | نتائج التوصيات وسلوك النظام |
| `Pharmacy Performance` | أداء الصيدليات والمبيعات |
| `Aggregated Reports` | جداول مجمعة للتقارير السريعة |

---

### 3.  AI / ML Feature Storage
> تخزين البيانات الجاهزة للذكاء الاصطناعي

**الغرض:** فصل عمليات الـ AI عن قواعد البيانات التشغيلية.

| البيانات المخزنة | الوصف |
|---|---|
| `Drug Feature Vectors` | التمثيل الرقمي للنصوص الطبية |
| `Similarity Matrices` | درجات التشابه بين الأدوية |
| `Embeddings` | Semantic Representations للأدوية |
| `Recommendation Features` | خصائص أنظمة التوصية |

---

### 4.  Logging & Monitoring Database
> مراقبة النظام والأخطاء والنشاطات

**الغرض:** استقرار النظام، تحسين الأداء، اكتشاف المشاكل.

| البيانات المخزنة | الوصف |
|---|---|
| `API Logs` | جميع الـ requests والـ responses |
| `Error Logs` | الأخطاء والاستثناءات |
| `User Activity Logs` | نشاطات المستخدمين |
| `Security Logs` | تسجيل الدخول ومحاولات الوصول |

---

### 5.  Future Vector Database *(قادم)*
> دعم البحث الذكي والـ AI المتقدم

**الغرض:** Semantic Search و Vector Similarity و AI Retrieval.

| البيانات المخزنة | الوصف |
|---|---|
| `Medical Embeddings` | التمثيلات الدلالية للأدوية والمصطلحات |
| `Search Embeddings` | تمثيل عمليات البحث |

##  Data Pipeline Architecture

### تدفق البيانات

```
Main Operational DB
        │
        ▼
  Extract Data          ← سحب البيانات المهمة فقط
        │
        ▼
 Clean & Transform      ← تنظيف، إزالة تكرار، توحيد نصوص
        │
        ▼
 Generate Analytics     ← إحصائيات، اتجاهات، سلوك مستخدمين
        │
        ▼
Generate AI Features    ← TF-IDF, Embeddings, Similarities
        │
        ▼
 Load Into Warehouse    ← تحميل كل البيانات المعالجة
        │
        ▼
  Train AI Models       ← تدريب على العلاقات والأنماط
        │
        ▼
Recommendation Engine   ← توصيات ذكية للمستخدم
```

---

### شرح كل مرحلة

#### 1️⃣ Main Operational DB
البيانات الأصلية — مستخدمون، صيدليات، أسعار، بحث، مخزون، طلبات.

#### 2️⃣ Extract Data
سحب البيانات المطلوبة فقط: عمليات البحث، الأسعار، المخزون، بيانات الأدوية.

#### 3️⃣ Clean & Transform
- حذف البيانات المكررة
- معالجة القيم الناقصة
- توحيد النصوص
- تجهيز البيانات للنماذج

#### 4️⃣ Generate Analytics
إنتاج إحصائيات جاهزة: أكثر الأدوية بحثاً، أنشط الصيدليات، تحليل الأسعار، سلوك المستخدمين.

#### 5️⃣ Generate AI Features
تحويل البيانات لـ features قابلة للاستخدام:
- TF-IDF Vectors
- حساب التشابهات
- تجهيز بيانات التوصية والبحث الذكي

#### 6️⃣ Load Into Warehouse
تحميل البيانات المعالجة في الـ Data Warehouse — المرجع الرئيسي للتحليلات والـ AI.

#### 7️⃣ Train AI Models
تدريب النماذج على:
- العلاقات بين الأدوية
- أنماط البحث
- التشابهات الطبية

#### 8️⃣ Recommendation Engine
توصيات ذكية بناءً على البيانات الطبية، الأسعار، التوفر، وسلوك المستخدمين.
