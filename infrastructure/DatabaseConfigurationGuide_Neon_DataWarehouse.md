# Neon Data Warehouse Configuration Guide

## Overview

This document describes the configuration and usage of the project's Data Warehouse database.

The MediSearch project uses a dedicated Neon PostgreSQL database as the Data Warehouse layer, completely separated from the Main Operational Database.

The warehouse stores analytics-ready data generated by the ETL pipeline and is optimized for reporting, business intelligence, dashboards, and machine learning.

---

# Purpose

The Data Warehouse is responsible for storing:

- Fact Tables
- Dimension Tables
- Aggregated Data
- Historical Data
- Business Metrics
- AI Features
- Analytics Datasets

This database is **NOT** used by the web application directly.

# Python Connection

Install PostgreSQL Driver

```bash
pip install psycopg2-binary
```

Example:

```python
import psycopg2

connection = psycopg2.connect(
    host="YOUR_HOST",
    port=5432,
    database="YOUR_DATABASE",
    user="YOUR_USERNAME",
    password="YOUR_PASSWORD",
    sslmode="require"
)

cursor = connection.cursor()

print("Connected Successfully")
```

# Used By

The Data Warehouse is accessed by:

- ETL Pipelines
- Warehouse Loading Pipelines
- Analytics Services
- BI Dashboards
- Machine Learning Pipelines
- Recommendation Engine

The frontend application should **never** connect directly to this database.

---

# Best Practices

✅ Store analytics-ready data only.

✅ Keep historical records.

✅ Use surrogate keys.

✅ Design Fact and Dimension tables.

✅ Optimize for analytical queries.

❌ Do not store raw data.

❌ Do not connect the web application directly.

❌ Do not use this database for transactional operations.
